# Charger session timing diagnostics beta

Diagnostic prerelease for investigating charger-managed sessions that are missed or recorded with a shorter duration than the physical motor run. Stable remains v0.7.39.

## Changes

- Add debug-only timing traces for charger advertisement arrival, scanner source, RSSI, packet age, connection scheduling, lock waits, connection duration, snapshot reads and disconnects.
- Correlate charger brush/session state, provisional confirmation, FF04/FF08 timer reads, post-session read attempts, negative acknowledgements, timeout types and retained-record reconciliation outcomes.
- Include a startup build marker so an active diagnostic installation can be verified.

The diagnostic build preserves the existing Bluetooth request sequence, polling intervals, session confirmation and reconciliation rules. It is evidence collection, not a claimed fix.

## Validation

385 tests pass in the pinned Python 3.12 / Home Assistant 2024.4.4 environment. The additional tests verify that debug logging preserves the exact Bluetooth write sequence, negative acknowledgements do not become successful reads, timeouts clean up pending requests, and unrelated payload bytes are omitted.

## Install and capture

Install v0.7.40b1 through HACS Redownload and restart Home Assistant. Enable debug logging for Oral-B Live, verify the `diagnostic_start` marker reports build `0.7.40b1`, then run the motor for a measured 30 seconds while noting whether the iO Sense display follows it. Stop, redock and allow at least 30 seconds for pause finalization and post-session reads.

Debug logs contain local Bluetooth device identifiers, timing and selected brush telemetry. Keep captures private unless deliberately sharing a relevant excerpt. Disabling debug logging stops the timing traces. To return to stable, select v0.7.39 in HACS and restart Home Assistant.
