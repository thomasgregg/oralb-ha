# Session display-face capture and pacer diagnostics

## Changes

### Keep the session result face across every delivery path

- Associate a completed session's display face from ending advertisements, direct FF0A notifications, direct FF0A reads, and iO Sense charger-forwarded FF0A reads.
- Read FF0A immediately after a directly connected session with short bounded retries because the optional notification is not reliable on every handle/session.
- Retain the brush connection throughout; Oral-B Live does not disconnect to force an advertisement or risk giving up the brush's single connection slot.
- Treat `display_face: null` as the normal "result unavailable" outcome. `off`, `standard`, an expired value, or an older session's result is never substituted.
- Freeze the first correlated result so a later display/menu change cannot overwrite it.
- Preserve a captured result across Home Assistant restarts and matching FF29 reconciliation, while preventing stale restore data or delayed retry tasks from leaking into newer sessions.
- Prioritize the transient charger-forwarded FF0A read immediately after the post-session battery read.

This completes the connected-session follow-up reported in #18.

### Toothbrush pacer diagnostic capture

- Add a separate read-only `iosense_probe.py --brush-pacer` mode for sector-count and pacing investigations.
- Capture raw FF02 plus initial/final FF25, FF26 and FF09 reads.
- Capture a complete FF04/FF07/FF08/FF09 notification stream for one brushing session.
- Add documentation, selection safeguards, cleanup behavior, and offline regression coverage for the diagnostic workflow discussed in #20.
