# Off-charger battery refresh and reliable session recovery

This stable release brings together the v0.7.39 beta fixes and additional protections against duplicate session recovery. Battery readings can refresh promptly after brushing away from the charger in Charger/app compatible mode.

## Changes

- Read and publish current battery during quiet summary states, independently of the retained session record. Preserve connection cooldowns, bounded reads, and the pause/record settlement delays.
- Preserve completed sessions through abandoned menu wakes, and date real brushing from motor/timer evidence. Use the advertised timer when Home Assistant first observes an already-running brush.
- Recover retained summaries without inventing a new start date or count when the brush clock is missing, incomplete, or earlier than the recorded session end. Retry recovery when a usable clock becomes available; current battery updates continue independently.
- Persist recent native timestamp, session-ID, and user-ID identities across reloads. Ignore older replays, distinguish sessions after brush-clock changes, and migrate existing timestamp-only storage.
- Serialize retained-record processing and protect newer brushing sessions from delayed reads, storage operations, and charger callbacks.
- Preserve captured display faces when refining the same session. Read transient face results early when supported and prevent older results from attaching to a newer session.

## Validation

All 378 automated tests pass locally in the pinned Python 3.12 / Home Assistant 2024.4.4 environment. This includes 79 reconciliation regression cases covering unusable clocks, delayed recovery, late advertisements, reloads and storage migration, midnight/time zones, pause/resume, distinct sessions, malformed records/storage, and concurrent reads and writes.

The [reporter's beta-2 feedback](https://github.com/thomasgregg/oralb-ha/issues/39#issuecomment-6234984558) confirmed prompt off-charger battery updates, correct dates and daily counts, and pause/separate-session handling on an iO Series 5, protocol 7, firmware 36. The additional reconciliation fixes have automated coverage; the single reported phantom entry had no debug log, so its exact cause has not been confirmed on that hardware.

## Compatibility and remaining observations

- A display face remains unavailable when the handle does not expose FF0A. The reporter's iO Series 5 returned characteristic-not-found for every attempt; this release does not add hardware support for it.
- Battery percentages are the brush's reported values. The observed drop/rebound is not smoothed or interpreted as a confirmed cell fault.
- Protocol-6 retained records remain protected from interpretation as the protocol-7/8 layout.
- A separate HA Direct battery-unknown report still needs connection/model details and is not claimed as resolved here.

## Install

Update Oral-B Live to **v0.7.39** through HACS and restart Home Assistant. Beta selection is not required. Existing beta users can select the stable version through HACS Redownload if it is not offered automatically.
