# Protocol-aware retained sessions

This beta fixes the immediate protocol-6 battery corruption reported in #33 without guessing the unknown protocol-6 `FF29` layout.

## Changes

- Select the retained-session decoder using the brush's exact BLE protocol version.
- Keep the verified protocol-7/8 decoder unchanged and preserve existing protocol-9 compatibility.
- On protocol 6, retain the valid `FF05` battery and locally reconstructed session instead of decoding `FF29` with the wrong layout.
- Preserve the raw `ff29_raw` value for continued protocol research.
- Treat a known unsupported layout as resolved for that session, preventing repeated connection attempts.
- Keep missing identity and malformed/read failures retriable.

## Protocol-6 validation

1. In HACS, enable prereleases for Oral-B Live and select **v0.7.36b2**.
2. Restart Home Assistant.
3. Wake the brush and complete a normal session.
4. Confirm that the Battery entity matches the handle and is no longer replaced with `0%` by a retained session.
5. Please continue with the structured capture set requested in #33 so the separate protocol-6 `FF29` decoder can be implemented from real evidence.

Until that decoder is mapped, protocol-6 live values and locally reconstructed sessions continue working, but the extra retained-session refinements from `FF29` are intentionally not applied.

Validation: 172 tests, HACS validation, and Hassfest all pass.
