# Bounded charger requests

This stable release prevents a stalled Bluetooth write from blocking queued charger reads. It includes the timeout fix tested in v0.7.40b2 and removes the temporary detailed timing diagnostics from both betas.

## Changes

- Apply one 1.5-second deadline to each native charger GET or toothbrush passthrough transaction, covering all Bluetooth writes and the response wait.
- Clean up a timed-out request and release the shared request lock so queued post-session battery and retained-result reads can proceed. Preserve caller cancellation, successful write ordering, and response matching.
- Remove temporary startup markers, per-request timing traces, advertisement traces, and raw passthrough payload logging. Standard troubleshooting logs remain available; enabling debug logging is not required.

## Validation

All 404 automated tests pass in the pinned Python 3.12 / Home Assistant 2024.4.4 environment. The 19 deadline regression cases cover stalled writes, a shared write/response budget, queued post-session recovery, cancellation, cleanup, successful reads, and unrelated late responses. Eight cases reproduced the weakness before the timeout fix. Independent review confirmed that removing the temporary instrumentation preserves the timeout fix and existing session behavior.

This addresses a demonstrated request delay. The cause of an entirely missed live session remains unconfirmed. Cancellation cannot retract a Bluetooth command already sent, and the protocol has no transaction IDs to distinguish identical late responses.

## Install

Update Oral-B Live to **v0.7.40** through HACS and restart Home Assistant. Beta users can select v0.7.40 through HACS Redownload if it is not offered automatically.
