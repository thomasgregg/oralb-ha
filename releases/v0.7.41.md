# Reliable Bluetooth client cleanup

## Changes

- Release Bluetooth client resources after a remote disconnect, even when the brush or iO Sense charger already reports the connection as closed.
- Complete old-client cleanup before reconnecting. Ignore delayed or duplicate disconnect callbacks from an old client so they cannot clear a replacement connection.
- Keep cleanup running when its caller is cancelled, wait for pending cleanup during unload, and release clients returned during shutdown or interrupted setup.
- End charger session ownership on explicit disconnect even if the Bluetooth backend does not deliver a callback.

This addresses the missing cleanup paths in [issue #49](https://github.com/thomasgregg/oralb-ha/issues/49). Thanks to @mtheli for the report and the linked Sonicare fix.

## Validation

All 441 automated tests pass in the pinned Python 3.12 / Home Assistant 2024.4.4 environment. The 37 cleanup cases also pass in the newer local Home Assistant / Python 3.14 environment. Coverage includes both transports, stale-client replacement, repeated remote loss, delayed and duplicate callbacks, thread handoff, cancellation, shutdown, backend errors, and eager task creation.

The tests verify cleanup calls with simulated clients. Duplicate Oral-B notifications have not been reproduced on Linux hardware. The minimum test environment uses bleak 0.21.1, which already closes its BlueZ bus on remote loss; bleak 3.0.2 requires the explicit disconnect now performed here. Temporary history and battery reads retain their existing deadline policy.

## Install

Update Oral-B Live to **v0.7.41** through HACS and restart Home Assistant.
