# Avoid repeated reads of unavailable display results

## Changes

- Stop repeated optional FF0A display-result reads and failure logs after an FF0A-specific not-found error is corroborated by a usable service table containing state and battery characteristics but no FF0A.
- Scope absence evidence to the Bluetooth client and discovered services. Reconsider it on reconnect, replacement or changed service tables, and actual FF0A notifications. Do not blacklist brush models or protocols.
- Preserve bounded retries for transient errors, timeouts, empty/off results, and uncertain discovery. Keep battery publication, retained-session recovery, and session-result association independent of this optional feature.

Addresses [issue #45](https://github.com/thomasgregg/oralb-ha/issues/45), based on @Heronidas's iO Series 5 hardware feedback in #39. This reduces unnecessary reads when the characteristic is absent; it does not add display-result support to unsupported hardware.

## Validation

All 488 tests pass in the pinned Python 3.12 / Home Assistant 2024.4.4 environment. All 47 FF0A capability cases also pass with Home Assistant 2026.8.3, bleak 3.0.2, and Python 3.14.

Coverage includes both capture paths, repeated capture, misleading error messages, incomplete or unavailable discovery, service changes during outstanding reads, reused and replacement clients, notifications contradicting absence, delayed old-session results, and independent battery/history recovery. Three original cases reproduced the unnecessary retries before the fix. Tests simulate transport and discovery; physical firmware capability remains hardware-dependent.

## Install

Update Oral-B Live to **v0.7.42** through HACS and restart Home Assistant.
