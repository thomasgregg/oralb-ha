# Session recovery and BLE reliability

This stable release promotes the fixes validated in v0.7.38b1, including confirmation on the affected protocol-6 hardware from #33.

## Changes

- Prevents a late selection-menu timer tail from replacing or counting a completed brushing session a second time.
- Restores and resets Sessions Today using the Home Assistant local date, including midnight rollover and migration of older restored state.
- Performs one bounded uncached GATT rediscovery when the mandatory Oral-B service data is missing after connecting.
- Keeps FF05 battery refresh independent from FF29 retained-session handling, so an unsupported or failed retained-session read cannot suppress valid battery data.
- Treats protocol-6 FF05 remaining time `00 00` as unavailable while preserving the reported battery percentage. Existing protocol-8 zero-runtime behavior is unchanged.
- Replaces the deprecated charger `via_device` reference with registry-safe Home Assistant device linking.

## Protocol 6

Protocol-6 FF29 retained-session decoding remains intentionally disabled until fresh correlated samples establish its layout. The debug-only FF29, FF22, and FF05 correlation logging remains available when Home Assistant debug logging is explicitly enabled; normal installations do not expose temporary diagnostic entities.

## Validation

- The affected protocol-6 brush confirmed one physical session is finalized once, the handle and entity battery percentages agree, and unavailable remaining time no longer appears as zero seconds.
- 193 tests passed in both the pinned and current Home Assistant environments, with 30 additional compatibility subtests in the current environment.
- GitHub Unit tests, HACS validation, and Hassfest validation passed on the stable release commit.
