# v0.7.33 — Session verdicts and drive diagnostics

## Changes

### Keep `standard` as the lowest completed-session verdict

- Treat FF0A raw value `1` (`standard`) as a genuine result face instead of discarding it as unavailable.
- Continue treating raw value `0` (`off`) as no captured verdict, so `display_face` remains `null` when the handle exposes no usable result.
- Preserve the existing bounded per-session association, first-result freeze, stale-generation rejection, restart restoration and no-disconnect behavior introduced in v0.7.31.
- Cover `standard` across ending advertisements, direct FF0A notifications, notification ordering around idle, direct retry reads and iO Sense charger-forwarded FF0A.
- Verify that a captured `standard` survives later display changes, while late values outside the capture window and failed/`off`-only reads remain excluded.

This corrects the follow-up finding reported and locally verified in #18.

### Calibrate the FF0B drive diagnostics

- Present the first FF0B drive word as **Oscillation angle** in degrees after converting the captured centidegree value.
- Preserve the original wire value in the entity's `raw` attribute.
- Rename the second diagnostic to **Drive target (raw)** without assigning an unsupported physical unit or meaning.
- Keep the historical entity keys and entity IDs (`motor_angle_raw` and `motor_target_raw`) so existing dashboards and automations continue to resolve.
- Document the measured mode/pressure behavior, known limitations and protocol evidence in the README and protocol reference.

Recorder history from v0.7.32 may contain the earlier unitless angle words; new values are recorded in degrees.
