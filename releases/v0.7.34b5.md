# v0.7.34b5 — Pacer and charger confirmation beta

Fifth cumulative beta validation build for #20 and #21. It includes all earlier v0.7.34 beta fixes.

## Pacer hardening for #20

- A valid FF26 timer schedule is authoritative when FF09 supplies a conflicting total hint.
- A successfully read but empty FF26 schedule makes the firmware-dependent FF09 total hint untrusted.
- The empty-schedule path no longer publishes an erroneous eight-sector count or maps the final 0xFF sentinel to sector_8.
- Genuine configured four-, six-, and eight-sector schedules remain supported.
- A failed FF26 read still permits the existing FF09 fallback.

## Charger session hardening for #21

- Charger brush_status pre_run is provisional and starts only read-only confirmation polling.
- Provisional polling checks FF04 and advancing FF08 values without exposing running, pressure, timer, or a brushing session.
- Native run, active_running, FF04 running, or an advancing FF08 timer promotes the provisional state to a confirmed session.
- Quiet charger states, charger unavailability, and transport disconnects discard provisional ownership immediately and end confirmed ownership cleanly.
- FF0B pressure polling begins only after confirmation.

3. If practical, disconnect or power off the charger during a provisional pre_run and confirm no stale running/pressure state survives.
