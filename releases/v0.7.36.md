# v0.7.36 — Protocol 6 battery compatibility

This release prevents retained-session data from replacing a valid protocol-6 battery reading with `0%`.

## Changes

- Select the `FF29` retained-session decoder through an exact BLE protocol-version registry.
- Preserve valid protocol-6 `FF05` battery readings and locally reconstructed sessions.
- Keep raw protocol-6 `ff29_raw` data available for diagnostics without interpreting it using the protocol-7/8 layout.
- Resolve known unsupported layouts without repeated Bluetooth retry attempts.
- Preserve the existing protocol-7/8 decoder and protocol-9 compatibility.
- Keep unknown identity and temporary read failures eligible for safe bounded retries.

The fix was confirmed by the affected protocol-6 firmware-107 reporter: after a normal session, `FF05 = 53 00 00 00` remained **83%**, matching the toothbrush display exactly.

Protocol-6 live values and locally reconstructed sessions continue working. The additional retained-session refinements from `FF29` remain intentionally disabled until the separate layout is mapped from the controlled captures tracked in #33.

Validation: 172 tests, HACS validation, and Hassfest all pass.
