# v0.7.39b1 — Off-charger battery refresh beta

This beta addresses #39: battery readings could remain stale when a brush stayed off the charger and moved straight from brushing through its summary/menu screens to sleep.

Implementation and test coverage: https://github.com/thomasgregg/oralb-ha/pull/40.

- Reads and publishes current battery in quiet summary states without waiting for the retained session record.
- Keeps the 20-second pause grace and 30-second retained-record settle delay.
- Retries using recent Bluetooth history even when unchanged advertisements do not trigger callbacks, with a 60-second minimum interval between connection attempts.
- Prevents older retained-session battery and restored metadata from replacing fresher readings.
- Bounds temporary reads/connections and cleans up cancellation during service-cache recovery.

This is an opt-in prerelease for hardware testing. The stable release remains v0.7.38. All 262 tests pass against the pinned Home Assistant 2024.4.4 / Python 3.12 environment, including 69 new regression tests. Real Bluetooth timing and firmware support still need confirmation.

GitHub Unit tests, HACS and Hassfest checks all passed: https://github.com/thomasgregg/oralb-ha/actions/runs/36918965143.

## Install through HACS

Enable prereleases/beta versions for Oral-B Live in HACS, select **v0.7.39b1**, and restart Home Assistant. Depending on your HACS version, use **Redownload** and its version selector; the HACS repository's prerelease switch controls beta update checks: https://hacs.dev/docs/use/entities/switch/.

## Help test #39

1. Keep **Charger/app compatible** mode, close the Oral-B phone app, and enable debug logging for Oral-B Live. For the off-charger fallback test, confirm the toothbrush state entity's `charger_address` is `null`; a matched iO Sense uses its bridge instead.
2. Note the battery entity's percentage, `last_read` and `source`, plus Sessions today.
3. Brush normally away from the charger, then leave the handle through summary → menu → sleep. Check whether battery `last_read` advances while the summary is visible. The percentage can stay the same after a valid read; battery `source` should become `direct_brush`. The toothbrush state may still have `data_source: advertisement`.
4. Confirm one session is counted and its duration matches the handle. If practical, pause for 5–10 seconds and resume without resetting the timer; that should still produce one session.
5. Disable debug logging to download the log and report the result on #39, including stop time, battery attributes and any unexpected duration/count changes.

A recent connection can delay another attempt until the 60-second cooldown expires. Hardware connection latency also affects the update time. You can return to v0.7.38 using HACS's version selector and restart Home Assistant.
