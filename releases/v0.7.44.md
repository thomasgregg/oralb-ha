# Recover charger links and missed brushing sessions

This stable release fixes iO Sense discovery after Home Assistant restarts and includes the passive-session and protocol-6 capture improvements from v0.7.44b1.

## Charger discovery and live data

- Queue nearby iO Sense chargers for verification after startup. Retry temporarily unavailable routes and missed identity replies even when the advertisement stays unchanged. Verify the paired brush again after a pairing change or a route loss.
- Match replies to the current request and connection. Ignore early, unrelated, duplicate, and incomplete status replies. Limit how long stalled subscriptions and characteristic reads can block setup.
- Reconnect when a live charger link stops returning usable data. Preserve the original brushing session when the brush timer continues after recovery. The estimated dashboard timer no longer adds time to saved sessions.

Thanks to @fratei for reporting the setup, identifying the discovery failures, and contributing the retry proposal and tests. [Issue #58](https://github.com/thomasgregg/oralb-ha/issues/58) · [PR #59](https://github.com/thomasgregg/oralb-ha/pull/59)

## Passive sessions and protocol-6 captures

- Recover missed passive stops using the last observed brushing sample. A near-zero timer followed by forward progress after a gap can identify the next session. Menu-only wakes stay provisional, and advertised sectors count after brushing is confirmed.
- Prefer the quiet-state display face over the provisional pre-stop face from the same session.
- Retry incomplete protocol-6 `FF29`/`FF22` capture pairs in a later quiet window. A valid `FF05` battery reading still updates independently. Debug logs show the failing read stage and why a retry was deferred.

Protocol-6 `FF29` field decoding remains disabled pending correlated captures. The first usable `FF29` read provides a baseline, and a complete pair can still describe an older session. [Issue #38](https://github.com/thomasgregg/oralb-ha/issues/38) · [Protocol-6 capture guide](https://github.com/thomasgregg/oralb-ha/blob/v0.7.44/docs/protocol.md#protocol-6-captures)

## Validation

The complete suite passed on Home Assistant 2024.4.4 and 2026.8.3. The restart regression simulates two chargers, one ESPHome proxy slot, unchanged advertisements, and 850 ms replies. Both brushes recover their charger association and live measurements. The reporter’s physical Home Assistant 2026.11.3 setup still needs confirmation with this release.

## Install

Install **v0.7.44** from Home Assistant Marketplace or HACS, then restart Home Assistant. For a manual update, extract `oralb_live.zip` into `config/custom_components/oralb_live` before restarting.
