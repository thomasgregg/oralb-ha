# Recover missed brushing stops and improve protocol-6 captures

This beta addresses passive session tracking and capture failures investigated in [issue #38](https://github.com/thomasgregg/oralb-ha/issues/38). Protocol-6 FF29 field decoding remains disabled. FF05 supplies current battery data.

## Changes

- Recover a missed passive stop using the last observed brushing sample. A near-zero timer followed by forward progress after a gap can distinguish two sessions even if Home Assistant missed the quiet-state transition.
- Keep a menu-only wake provisional during pause grace. Count advertised sectors once brushing is confirmed.
- Give the quiet-state advertisement face precedence over a provisional pre-stop advertisement face for the same session.
- Keep incomplete protocol-6 FF29/FF22 pairs eligible for a later quiet-window retry. A valid FF05 battery reading publishes independently.
- Explain the failing read stage and retry deferrals in the debug log. A first usable FF29 read establishes the comparison baseline, and a complete pair can still contain an older session.

## Validation

All 519 tests passed on Home Assistant 2024.4.4 and 2026.8.3. The session and Bluetooth tests simulate transport. The [protocol-6 capture guide](https://github.com/thomasgregg/oralb-ha/blob/v0.7.44b1/docs/protocol.md#protocol-6-captures) describes the baseline and follow-up hardware run needed for mapping.

## Install

Select **v0.7.44b1** from the prerelease versions in HACS and restart Home Assistant.
