# Bounded charger requests beta

This beta fixes a demonstrated charger-request timeout weakness that can delay post-session battery and retained-result reads. It retains the timing diagnostics from v0.7.40b1. Stable remains v0.7.39.

## Changes

- Apply one 1.5-second deadline to each native charger GET or toothbrush passthrough transaction, covering every Bluetooth write and the response wait.
- Cancel a stalled transaction before releasing the shared request lock, allowing queued post-session reads to proceed without overlapping an abandoned write coroutine.
- Preserve pending-request cleanup, caller cancellation, successful write ordering and matching of responses to their requested characteristic. Queue waiting remains outside the next transaction's wire budget.

## Validation

The 19 new regression cases were written before changing the implementation. Eight reproduced the timeout weakness on the old code; the other eleven covered successful reads, cancellation, cleanup, queue waiting and unrelated late responses. All 404 tests now pass in the pinned Python 3.12 / Home Assistant 2024.4.4 environment.

The simulated post-session case verifies that a battery read queued behind a stalled timer request can complete before the simulated brush connection closes, with at most one write coroutine active. Independent code review found no blocking issue in this narrow change.

## Hardware testing and limitations

Install v0.7.40b2 through HACS Redownload and restart Home Assistant. Debug logging includes a `diagnostic_start` marker for build `0.7.40b2`. Check that an ordinary charger-managed session records its duration once, and that subsequent charger requests remain usable after a timeout.

This patch addresses the observed blocked-request delay. It does not establish the cause of an entirely missed live session, guarantee retained-result availability after docking, or guarantee that cancellation retracts a Bluetooth command already sent to the charger. The wire protocol does not provide transaction IDs to distinguish identical late responses.

Debug captures contain local device identifiers and brush telemetry; keep captures private unless deliberately sharing an excerpt. To return to stable, select v0.7.39 in HACS and restart Home Assistant.
