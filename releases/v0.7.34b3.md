# v0.7.34b3 — Pause/resume session beta

Beta validation build for #22.

This build treats a temporarily paused and resumed brushing run as one logical Home Assistant session when the authoritative brush timer continues:

- A quiet motor edge remains provisional for a bounded 20-second grace period.
- Forward/equal timer continuation merges resumed fragments while a coherent reset near zero creates a genuinely new session.
- The original start, cumulative final duration, covered sectors, and pressure summary are preserved across pauses.
- Interim pause faces are discarded; only the final completed-session display face is retained.
- Late FF29 summaries refine the combined session without increasing sessions_today again.
- Stale events, timeout generations, charger-extrapolated ticks, and delayed reset evidence are guarded against cross-session merges.

## Targeted hardware validation requested

1. Pause and resume one brushing run several times, with each pause under 20 seconds. Confirm sessions_today increases once and Last session shows the cumulative timer, combined sector/pressure summary, and final face.
2. End a session without resuming. Confirm Last session appears after about 20 seconds and is counted once.
3. Start a genuinely new session shortly afterward. Confirm a timer reset near zero produces a separate record even when the gap is short or selection_menu appears first.
4. In charger mode, repeat the pause/resume case and confirm the retained FF29 summary refines the same completed session without recounting it.

Automated validation passed on the minimum Home Assistant 2024.4 / Python 3.12 lane and the current Home Assistant 2026.8 / Python 3.14 lane, plus HACS and Hassfest.

HACS testers must opt into pre-releases for the Oral-B Live repository or choose v0.7.34b3 under Need a different version, then restart Home Assistant.
