# v0.7.39b2 — Session recovery and early display-face capture beta

This second beta addresses the session-date/count and missing display-face reports from [issue #39](https://github.com/thomasgregg/oralb-ha/issues/39#issuecomment-5996061651). The prompt off-charger battery refresh from beta 1 is retained.

## Changes since beta 1

- Discard an abandoned, unconfirmed menu wake when the brush becomes unavailable. Preserve the previous completed session and any pending pause grace, rather than finalizing it prematurely.
- Date menu-confirmed brushing from motor/timer evidence, including starts after local midnight before Home Assistant declares the old menu unavailable. Expire cached continuation candidates after their existing two-minute matching window.
- Publish FF05 battery first, then read transient FF0A in the same initial quiet connection. Retry briefly with production delays while its 15-second capture window remains open; keep the 30-second FF29 settlement and 60-second connection cooldown.
- Apply face readings immediately and check the original session token before and after I/O, preventing old results from being assigned to newer sessions.

## Validation

290 automated tests pass, including 28 new tests with parameterized timer, time-zone, protocol, and face cases. Tests cover the real Home Assistant unavailable callback, overnight recovery, pause preservation, timer resets, delayed/failed reads, deadline boundaries, cancellation, charger discovery, and stale-result races. Unit tests, HACS, and Hassfest also pass in GitHub Actions.

This is a prerelease for hardware testing. Face capture remains best effort if the brush supplies no FF0A result or a connection cannot be made during the capture window. The reported 26% to 16% battery change is still under observation; this beta does not smooth or alter the brush's reported percentage.

## Install and test

In HACS, open Oral-B Live, choose **Redownload**, then **Need a different version?**, select **v0.7.39b2**, download, and restart Home Assistant. See the [HACS dashboard documentation](https://hacs.netlify.app/docs/use/repositories/dashboard/).

Please check:

1. An ordinary off-charger session: battery refresh, session date/count, and the last-session `display_face` and its source.
2. Menu-only wake followed by sleep/unavailability, then a real session the next day: correct new start and exactly one increment.
3. Several short pauses during one brushing: one combined session with the final duration/result.
4. Two separate sessions with a reset timer: two increments.

If the face is still missing, please report the model/firmware, mode, stop timestamp, `smiley_raw`, `display_face`, and `display_face_source`; debug logs around the stop are helpful. If the battery drop repeats after a full charge, include both percentages with their `battery_source` and `battery_updated_at` values, and raw FF05 if available.

Stable remains [v0.7.38](https://github.com/thomasgregg/oralb-ha/releases/tag/v0.7.38). To compare beta behavior, the previous [v0.7.39b1](https://github.com/thomasgregg/oralb-ha/releases/tag/v0.7.39b1) remains available through HACS Redownload.
